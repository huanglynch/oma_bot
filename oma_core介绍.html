核心特点与优势

👥

Orchestrator + Worker 团队协作

根角色规划与派发，Worker 按租约并行。Board 是唯一协作面。Playbook 只生成看板项，不另起流水线引擎。

⚡

多 Bot 真并发执行

通过 max_concurrent_bots 控制并发槽位，所有子 Bot 运行在独立线程，互不阻塞，collect 模式让 root 在等待时继续推进其他工作。

🧩

流程自由定制

通过 Agent MD 文件定义角色、工具权限、模型选择；通过 Skill MD 注入专业知识；通过 App YAML 连接任意 REST API——无需修改一行 Python 代码。

🔌

App 连接器 · 零代码对接 API

用一份 YAML 声明将任意 HTTP REST API 变为 OMA 工具，内置 Bearer / Header / Basic / 无鉴权四种认证方式，支持路径参数与请求体，Agent 可自主发现并调用所有已注册 App。

🐝

Swarm 自动专家派发

基于关键词启发式自动识别任务类型，动态选取最匹配的专家 Bot 组合，并行分配互不冲突的写 Lease，一键开启无需手写派发逻辑。

📋

Board 看板任务追踪

Kanban 式状态机（ready → running → done/blocked/failed）是团队协作的唯一真值，支持评论、转交、阻塞标记，实时可观测整个多 Bot 执行过程。

🔒

写 Lease 文件隔离

基于 glob 模式的文件独占锁机制，不同 Worker 的写权限严格隔离，orchestrator 完全禁止写文件，从根本上防止多 Bot 并发时的文件冲突。

💬

中断与审批工作流

ask_user（提问）与 approval（审批）两种中断类型，支持超时策略、会话级缓存、批量审批。既能全自动执行，也能在关键节点插入人工决策。

📊

上下文智能压缩

三档水位自动触发（70% / 85% / 95%），滑动窗口 + 摘要折叠 + 截断超限工具输出，保证长任务在任意 context 长度的模型上稳定运行不崩溃。

1

整体架构

系统分为 9 个垂直层次，各层职责单一，依赖方向自顶向下。GUI 层与业务逻辑完全解耦，Runtime 是核心执行引擎。

依赖原则

核心三方依赖仅 requests + pyyaml；GUI 加 nicegui；浏览器工具加 playwright。依赖方向严格自上而下，下层不导入上层。

核心设计哲学

Runtime 是唯一真值引擎；GUI 是派生视图；工具是受限副作用；TaskState 是持久状态主键；Board 是团队通信唯一渠道。

🧠 oma/llm.py — OpenAI 兼容 LLM 客户端

纯 requests 实现，不依赖 openai SDK。支持工具调用、自动重试。解析 agent 卡 model: main/fast；FAST 失败降级主模型。

🔄

自动重试

指数退避重试，HTTP 5xx 触发，4xx 直接返回错误。默认重试3次。

🌏

方言兼容

normalize_messages 将中间 system 消息改写为 user，避免 Qwen/vLLM 拒绝。

🧩

思考字段提取

按序尝试 content → reasoning_content → thinking，适配 DeepSeek-R1 等思考型模型。

⏱

频率控制

llm_min_interval 保证两次调用最小间隔，防速率限制。

📊 oma/context.py — TaskState 与上下文压缩

TaskState 是贯穿整个运行周期的状态主键，上下文压缩通过三档水位触发，防止 Token 超限。

三档压缩水位

触发条件行为
≥ 70% summary_watermark保留最近 sliding_window（默认12）轮，旧轮压缩进 <compacted> 摘要块
≥ 85% hard_watermark保留最近4轮，截断大体积 tool result（超800字符部分替换为省略提示）
≥ 95% 紧急水位注入紧急提示，要求立即 finish 或 ask_user
⚙️ oma/runtime.py — ReAct 执行引擎（核心）

实现 Reason+Act 循环，管理多 Bot 并发、Board 看板、Lease 写锁、Spawn/Collect 协议和中断机制。

公共 API

方法说明
start(goal, agent, swarm)创建 Run，初始化 root Bot，返回 run_id
step(run_id)执行一步（一次 LLM 调用 + 工具执行），返回事件字典
run_until_idle(run_id)循环 step 直到 waiting_user / done / error / cancelled
resume(run_id, interrupt_id, decision)回应中断（approve/deny/answer），恢复执行
pending(run_id)获取所有待处理中断列表
final_text(run_id)提取用户可见的最终回复文本
cancel(run_id)取消整个 Run，所有 Bot 状态变为 cancelled
board(run_id)获取当前 Board 快照

配置参考

完整的 oma_config.yaml 各字段说明，支持通过环境变量覆盖所有值。

agent 节

nameAgent 名称默认: main
model主模型，可写 {env:OMA_LLM_MODEL}必填
base_urlAPI 端点必填
api_keyBearer Token可空
temperature采样温度默认: 0.2
max_tokens单次最大 token默认: 8192
max_iterations单 Bot 最大迭代默认: 80

routing 节

enabled快慢分流开关，默认开true
main_model通常同 agent.modelOMA_LLM_MODEL
fast_model便宜模型，空则降级主模型OMA_FAST_MODEL

context 节

max_tokens上下文 token 上限默认: 128000
sliding_window70% 水位保留轮数默认: 12
summary_watermark轻度压缩触发点默认: 0.70
hard_watermark重度压缩触发点默认: 0.85
tool_result_max_chars工具结果最大字符数默认: 5000

team 节

enabled是否启用团队协作默认: true
default_waitspawn 默认等待模式默认: collect
child_max_iterations子 Bot 最大迭代数默认: 40
swarm.enabled是否启动 Swarm默认: false
swarm.max_workersSwarm 最大专家数默认: 3

interrupt 节

enabled是否允许中断默认: true
default_timeout_sec等待用户超时（秒）默认: 300
on_approval_timeout审批超时策略deny
max_questions_per_bot每 Bot 最大提问次数默认: 8
remember_session会话内缓存审批结果默认: true

带审批的危险操作（interrupt 机制）

▼
python
rt = Runtime(workspace=".")
run_id = rt.start("清理项目中所有 __pycache__ 目录")
while True:
    ev = rt.step(run_id)
    if ev["status"] == "waiting_user":
        for intr in rt.pending(run_id):
            ans = input(f"⚠️ 允许: {intr['payload']['args'].get('command','')} ? (y/n): ")
            rt.resume(run_id, intr["interrupt_id"], "approve" if ans=="y" else "deny")
    if ev["status"] in ("done","error","cancelled"): break

团队协作详解

orchestrator + worker 模式下的完整协作流程，Board 看板作为唯一通信渠道。

角色权限对比

能力orchestratorworkerany（默认）
写文件 / edit_file禁止lease范围内允许
执行 bash禁止lease范围内允许
spawn_agent允许禁止允许
upsert_item（创建）允许禁止允许
post_item（评论）允许允许允许

collect 模式（默认推荐）

子 Agent 后台异步运行，orchestrator 继续其他工作，需要结果时调用 collect_agent("ready")。并发效率高，适合独立子任务。

sync 模式

阻塞等待子 Agent 完成，直接返回结果。适合有严格依赖关系的串行子任务。

⚠️
关键约束：orchestrator 不可调用 write_file / edit_file / bash，违反此约束会抛出 ToolError。Worker 之间通过 post_item 评论通信。根 bot 在 Board 仍有 ready/running 项时不能 finish（除非 force 并写「未完成」）。机械验收会检查 artifacts 路径是否存在且非空。
ℹ️
办公产物默认租约 swarm/<agent>/**。code-change 里 implementer 的 exclusive_globs 应改成 explorer 指出的代码路径，不要锁死 swarm/implementer/**。

App 连接器使用指南

通过 YAML 声明将任意 HTTP REST API 变为 OMA 工具，无需编写一行 Python 代码。

⚠️
当前工作区 .oma/apps/github.yaml 指向 api.github.com（需 GITHUB_TOKEN）。 mail.yaml / calendar.yaml / docs.yaml 仍是 example 域名，视为未接通：inbox / planner 只处理粘贴文本，禁止对假域名做发送测试。
.oma/apps/jira.yaml
name: jira
base_url: https://yourcompany.atlassian.net
auth:
  type: basic
  user_env: JIRA_EMAIL
  pass_env: JIRA_API_TOKEN
ops:
  list_issues:
    method: GET
    path: /rest/api/3/search
  get_issue:
    method: GET
    path: /rest/api/3/issue/{issueKey}
  create_issue:
    method: POST
    path: /rest/api/3/issue

支持的鉴权类型

类型配置示例说明

Bot & 编排

一份花名册、一套产物契约、Playbook 只 upsert Board。不另写调度引擎。办公岗在 .oma/agents，编码岗在 .opencode/agents。

数字员工不是「再堆人格」，而是 Catalog 名字 + Board + Lease + finish。 根 bot / orchestrator 命中流水线时 use_skill name=company-playbooks， 把步骤写成看板项再 spawn_agent / collect_agent。 工作台（Bots 标签）只是同一批 Catalog 的可视化入口，清单在 .opencode/oma_gui_bots.json。 编排模板另存在 .opencode/oma_gui_playbooks.json 与 .opencode/playbooks/*.json。Bots 编排页可新建 / 编辑 / AI 提案 / 导入导出， 保存后与 company-playbooks、oma/playbooks.py 三处 id 对齐。 爆款文章岗在 .oma/agents：viral-scout / viral-drafter / viral-editor，编排者 viral-orch。

Catalog 先出现的同名赢：工作区 .oma/agents → .opencode/agents → 配置里的 extra 目录 → 用户主目录 → 包内 oma/agents。default_bots/ 不在扫描路径，可删。

⑤ 日更与定时工位

日程写在工作区 .oma/schedule.json。GUI 配置窗「定时任务」页可查看、编辑、新建、启用/停用，并「立刻跑」某一条。

字段含义
id编号，不要重复
whendaily-05=本地 5 点后且当天未跑；daily=每次 runner 扫描；manual=只手动/立刻跑
enabledfalse 时 cron 跳过该条
agent编制里已有的岗位名，日更默认 researcher
goal交给该岗位的任务正文。日更示例：过去 24 小时可核验进展，产物写到 swarm/researcher/
cron
5 5 * * * cd /path/to/oma-core && python -m oma.schedule_runner --run
python -m oma.schedule_runner --run --once-id daily-24h-research --force

⑥ 快慢模型

子 agent 卡片的 model: 会传进 LLMClient。别名：main / 空 = 主模型；fast = 便宜模型。

项说明

和「四人格内容团队」差在哪？
岗位哲学同向：调研 → 选题 → 起草 → 终审。OMA 用现成 researcher / brief / writer / critic， 交接靠 swarm/<岗>/ 而不是共用一个大上下文。 还缺的是外部日历（Notion）和离线持续开工——后者用本机 cron + schedule.json 补，不必再造四个英文岗。
能力会不会因为契约变弱？
不会。工具集没减。变严的是乱写、编出处、假装已发送。 办公和调研因此更能交件；开发靠 explorer / implementer / qa / code-reviewer 闭环。
